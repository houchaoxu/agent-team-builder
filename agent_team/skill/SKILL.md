# Agent Team Runtime

用户只需描述目标。由当前 Agent 处理安装、环境准备、项目配置和内部工具调用，不向用户索要 CLI 参数、spec、host YAML 或命令行操作。默认独立完成简单任务；需要协作时再加载角色。宿主负责实际 Agent 调用与最终验收。

## 安装与首次启用

- 用户要求安装、给项目配置团队，或第一次启用时，阅读 [对话安装](references/installation.md)。优先项目范围，只有用户要求“所有项目可用”才选用户范围。
- 已安装时直接复用。内部引擎通过本 Skill 的 `scripts/run.py` 调用，不依赖全局 `agent-team` 命令或用户手动 pip。缺依赖时按安装说明由 Agent 准备隔离环境；遇到环境权限问题仅说明真实阻塞，不要求用户照抄脚本。
- 没有 Python、网络或执行工具时，按 [基础协作模式](references/basic-mode.md) 使用宿主文件工具。明确基础模式的能力，不能假装运行过完整引擎。
- 只在宿主确实发现 Skill、项目入口已写入并完成可执行的验证后报告安装成功。宿主未刷新时可请用户重新打开会话，不声称已自动生效。

## 项目与任务

- Agent 用内部 runner 执行 `--project <root> --platform <platform> init`。存在团队则恢复；配置损坏须报告修复，不重建覆盖。保留用户入口文件内容。
- 默认独立完成明确的小任务。此路径无需读取团队索引、角色全文或记忆，也不用创建完整任务计划。
- 对确有专业审查收益或多个独立交付物的任务，阅读 [任务编排契约](references/orchestration.md)，生成 spec，执行 `plan`。不要仅凭关键词组队。
- 团队不是常驻进程；新会话不重新安装角色。只读取本次选中角色和与任务相关的记忆。不要复制完整对话。

## 实际委派

本 Skill 请求在收益明确且环境允许时使用子 Agent。先查看当前宿主真实工具与角色列表，生成本次 `--host` 能力证据；不得从文件或历史会话推断可调用性。

以计划中的 batches 为顺序；同一批次内才可并行。使用宿主实际提供的 spawn/delegate 工具，传入计划的目标、上下文、写入边界、交付物和验收条件。每次调用保留真实返回的 Agent ID。工具不支持时按照交接包顺序执行，并明确由当前 Agent 执行各步骤。

告诉每个子 Agent：还有其他协作者，不得回退或覆盖用户和他人的修改。Reviewer 默认只读；写入范围是协作约定，不能代替宿主沙箱。主 Agent 处理接口、冲突、错误和最终验收。失败应记录失败状态，不能用规划成功代替执行成功。

## 能力扩展与记忆

需要推荐角色或计划出现能力缺口时，默认用宿主 LLM 理解用户原话、角色职责与交付物，按 [语义角色推荐](references/role-matching.md) 完成候选评估与校验。不要求中英文或能力标签精确相等，也不把精确匹配为空当作没有合适角色。程序只准备资料、校验评估，不自动调用外部模型 API。

无合适角色时才考虑 `role generate`。安装前用 `role install` 预览来源、内容和路径，仅在已有授权或用户确认后加 `--approve`。安装只写项目文件；当前会话是否重载成功仍须通过宿主实际验证。

任务真实执行后，用 `task update` 保存结果和验收 evidence；无法取得的 Token/时长保持 null。只对可长期复用、有来源的信息调用 `memory add`，架构/决策项按其确认要求处理。统计不能把缺测数据当零，也不能声称本系统保证 KV Cache 命中。
