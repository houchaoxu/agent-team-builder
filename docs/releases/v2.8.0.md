## Agent collaboration that adapts to the current host

Agent Team Builder now checks the capabilities available in the active session and routes collaboration accordingly. It can use a callable native specialist, pass role instructions to a generic subagent, create a temporary specialist when supported, or follow the specialist workflow sequentially when delegation is unavailable. Installation, discovery, registration, invocation, and returned results are treated as separate steps; a Skill file alone is not evidence that a native agent can be called.

- **One shared core, host-specific adapters:** Codex and Claude Code installation adapters package the shared workflow for their respective environments; WorkBuddy, Trae, Pi, and other hosts use capability evidence from the current session to select a supported execution path.
- **Agency-Agents as the default role library:** bundled role cards are pinned to an upstream revision, verified by hashes, and downloaded on demand. Other host-specific personal role directories are not searched unless the user explicitly asks to import them.
- **User-controlled role installation:** role matches are offered as choices. The agent previews the source, destination, and write scope, then waits for explicit confirmation before installation.
- **Progressive team loading:** simple tasks stay with the primary agent. Existing project teams and selected role instructions load only when collaboration has a clear benefit; teams are reused across sessions.
- **Honest capability reporting:** unavailable or unverified host features remain unknown instead of being presented as working integrations. Actual native-agent registration and invocation still depend on the installed host and need validation there.

The bundled 283-card index is sourced from a pinned Agency-Agents revision. No clone, extra model API, or vector database is required for role retrieval.

### Upgrade

Ask your agent to update Agent Team Builder to v2.8.0, preserve a rollback backup, and verify the installed version. New users can follow [INSTALL.md](https://github.com/houchaoxu/agent-team-builder/blob/v2.8.0/INSTALL.md). The release includes the complete Skill bundle and a SHA-256 checksum.

### Validation

The release workflow runs the complete Python test suite and validates that the stable tag, package version, and generated bundle manifest agree before publishing. Host-native discovery, registration, and invocation must still be verified in each specific product version; the release does not claim all hosts have passed live end-to-end tests.

## 让团队协作适配当前宿主

Agent Team Builder 会检查当前会话实际具备的能力，并据此选择协作方式：委派给可调用的原生专家、将角色指令交给通用子 Agent、在支持时创建临时专家，或在无法委派时按专家流程顺序执行。安装、发现、注册、调用和结果返回分别判断；仅有 Skill 文件不能证明原生 Agent 已可调用。

- **共享核心，宿主适配：** Codex 与 Claude Code 安装适配器分别为对应环境打包共享工作流；WorkBuddy、Trae、Pi 等宿主根据当前会话能力选择可用的执行路径。
- **Agency-Agents 是默认角色库：** 内置角色卡固定到上游 revision、通过哈希校验，并在需要时按需下载。除非用户明确要求导入，否则不会搜索其他宿主的个人角色目录。
- **用户决定是否安装角色：** 匹配后先提供角色选项。Agent 展示来源、目标位置和写入范围，收到明确确认后才安装。
- **渐进式加载团队：** 简单任务由主 Agent 直接处理；只有在协作确有帮助时，才加载已有项目团队和选中角色指令，并在后续会话中复用团队。
- **如实报告宿主能力：** 不可用或未经验证的能力保持未知，不会被描述为已完成的集成。原生角色的发现、注册和实际调用仍取决于具体宿主版本，需在宿主中验证。

内置的 283 张角色卡来自固定版本的 Agency-Agents，无需 clone 素材仓库，也不需要额外模型 API 或向量数据库。
